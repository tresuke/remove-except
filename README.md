# remove-except

[English](README.md) | [日本語](README.ja.md)

Have you ever wanted to keep only a few items among many files in a directory and remove everything else, including items in nested directories? I have. Of course, a script can do that. But I thought it would be more convenient to have a command that only requires the paths or patterns to keep. That is why I made `remove-except`.

`remove-except` is a command-line tool that keeps items matching any supplied path or glob pattern and deletes the other items under the selected directory.

## Safety Notice

This tool permanently deletes files and directories. Back up important data before running it. Before deleting anything, use `--dry-run` and review every item. `--summary` omits paths, so do not use it for the pre-deletion review. If none of the supplied keep patterns matches any item, everything under the selected directory becomes a deletion target. Especially when using `--force`, verify that the intended patterns match items. When passing patterns generated by another command with `--patterns-from-stdin`, also use `--dry-run` to verify that the generated patterns are what you intended. When using `--root`, verify that the displayed directory is the intended location. A filesystem's top-level directory cannot be selected for processing.

## Quick Start

The command syntax is `remove-except [OPTIONS] [KEEP_PATTERN]...`. Positional arguments specify paths or glob patterns to keep. With `--patterns-from-stdin`, provide at least one pattern across both sources; multiple patterns use OR semantics.

First, use `--dry-run` to review which items will be kept and deleted.

```sh
remove-except --dry-run keep.txt keep '**/*.md'
```

To perform deletion, omit `--dry-run`. In a normal run, the tool displays the kept items and deletion targets before asking for confirmation. See “Display and Execution” for the confirmation rules. With `--force`, deletion proceeds without prompting. Invalid patterns or an invalid directory still produce an error.

```sh
remove-except keep.txt keep '**/*.md'
remove-except --force keep.txt keep '**/*.md'
```

Use `--root` to select a different processing directory. Relative paths are resolved from the current directory when the command starts.

```sh
remove-except --root work --dry-run keep.txt '**/*.md'
```

## Options

| Option | Description |
| --- | --- |
| `[KEEP_PATTERN]...` | Paths or glob patterns to keep. At least one is required unless `--patterns-from-stdin` is used; multiple patterns use OR semantics. |
| `--root <PATH>` | Selects the directory to process. Defaults to the current directory when the command starts. Relative paths are resolved from that directory. |
| `-n`, `--dry-run` | Displays kept items and deletion targets without deleting anything. |
| `-f`, `--force` | Deletes without showing the confirmation prompt. Pattern and directory validation still apply. |
| `--patterns-from-stdin` | Reads keep patterns from standard input, one per line. They are combined with positional patterns using OR semantics. |
| `--format <FORMAT>` | Plan output format: `human` (default) or `json`. |
| `--layout <LAYOUT>` | Output layout: `tree` (default) or `flat`. |
| `--sort-by-type` | Flat layout only. Sorts by Directory, File, then Symlink. |
| `--summary <SECTION>` | Shows counts for `keep`, `delete`, or `both` instead of paths in the selected sections. |
| `-h`, `--help` | Displays help. |
| `-V`, `--version` | Displays the version. |

`--summary`, `--layout`, and `--sort-by-type` are only for human-readable output (`--format human`) and cannot be combined with `--format json`.

## Patterns and Processing Rules

### Example

The following example assumes `work` is the current directory.

```text
work/
├── keep.txt
├── readme.md
├── todo.txt
├── reports/
│   ├── summary.txt
│   ├── report1.csv
│   ├── report2.csv
│   └── 2025/
│       ├── annual.csv
│       └── notes.txt
└── archive/
    └── old.csv
```

### Glob Patterns

You can use glob patterns to specify paths to keep. Characters such as `*` and `?` represent parts of item names or directory levels. Patterns can match files, directories, and symbolic links. Separate multiple patterns with spaces.

```sh
remove-except --dry-run '**/*.md'
```

In this example tree, `readme.md` is kept, while `keep.txt`, `todo.txt`, `reports`, and `archive` are shown as deletion targets. The preview displays both kept items and deletion targets.

Common glob syntax:

| Pattern | Meaning |
| --- | --- |
| `*.md` | Item paths ending in `.md` directly under the processing directory. `*` does not cross `/`. |
| `**/*.md` | Item paths ending in `.md` directly under the processing directory or in nested directories. `**/` matches zero or more directory levels. |
| `reports/report?.csv` | `?` matches any single character except `/`. In this example, it matches `report1.csv` and `report2.csv`. |
| `reports/report[12].csv` | `[]` matches one of the listed characters. In this example, it matches `report1.csv` and `report2.csv`. |

To limit a glob to a particular subdirectory, include its path relative to the processing directory in the pattern.

```sh
remove-except --dry-run 'reports/**/*.csv'
```

In this example tree, the pattern keeps `reports/report1.csv`, `reports/report2.csv`, and `reports/2025/annual.csv`. Quote globs to prevent the shell from expanding them before the command runs.

### Selecting Subdirectories

To keep an entire subdirectory, specify its path without a glob.

```sh
remove-except --dry-run reports/2025
```

`reports/2025` and all of its contents are kept. For example, `annual.csv` and `notes.txt` remain, while `reports/summary.txt` and `reports/report1.csv` are deletion targets.

To keep only one file inside a subdirectory, specify its relative path.

```sh
remove-except --dry-run reports/2025/annual.csv
```

This keeps `annual.csv` and its parent directories, `reports` and `reports/2025`. The sibling file `notes.txt` is a deletion target.

To keep only certain file types within a subdirectory, combine its path with a glob.

```sh
remove-except --dry-run 'reports/2025/*.csv'
```

This example keeps `reports/2025/annual.csv`; `reports/2025/notes.txt` is a deletion target. Since `*` matches only within one level, `reports/2025/*.csv` is limited to CSV files directly under `reports/2025`. To include deeper levels, use `reports/2025/**/*.csv`. To keep the entire directory, specify its path, such as `reports/2025`, without a glob.

### Processing Scope and Paths

By default, the tool recursively processes the current directory from which it was started. Use `--root` to select another processing directory. A relative path supplied to `--root` is resolved from the startup directory. The selected directory itself is never listed or deleted. The filesystem's top-level directory is rejected for safety.

At least one keep pattern is required. Patterns are positional arguments or, with `--patterns-from-stdin`, lines read from standard input (see “Pipeline Integration”). With multiple patterns, an item is kept if it matches any one of them. Leading or trailing spaces are part of the item name. Quote patterns containing spaces so the shell passes each pattern as one argument.

Relative patterns are resolved from the selected processing directory. Absolute patterns are accepted only when they are inside that directory. Relative patterns and the portion of an absolute pattern after the matching directory prefix normalize `.` components and repeated separators; the prefix itself is not normalized. On Windows, `\` is converted to the `/` separator before matching. On Ubuntu, `\` is not a separator but a glob escape character. Patterns outside the selected directory, patterns containing `..` as a path component, empty patterns, and ambiguous Windows drive-relative paths (for example, `C:folder`) are errors.

Absolute patterns are compared with the processing directory after symbolic links and similar indirections are resolved (the path shown after `Root:` in the output). If `--root` or the current directory goes through a link, an absolute pattern written with the link path is treated as outside the processing directory and fails. Use relative patterns in that case.

### Matching and Retention

Patterns support `*`, `**`, `?`, character classes `[]`, and alternation `{a,b}`. Files, directories, and symbolic links can match. See the examples above for `*`, `**`, `?`, a character class, and path-separator behavior. See the rest of this section for alternation and retention rules.

A matched item and its parent directories are kept, but unmatched descendants are not. A directory path without a glob keeps that directory and all of its contents. `dir/*` matches only items directly under `dir`; it does not recursively keep the contents of matched subdirectories. `.` and `./` keep everything under the processing directory.

The glob characters are `*`, `?`, `[`, `{`, and `}`. On Ubuntu, `\` is also a glob character because it escapes the next character. A pattern containing any of them is treated as a glob and does not keep the contents of matched directories. For example, `reports/{2024,2025}` keeps only the two directories. To keep their contents too, append `/**`, as in `reports/{2024,2025}/**`, or specify `reports/2024` and `reports/2025` separately.

`dir/**` matches items under `dir` but not `dir` itself, so an empty `dir` becomes a deletion target. To keep a directory even when it is empty, specify `dir` without a glob.

To match a glob character literally, wrap it in a character class, such as `[*]`, `[?]`, `[[]`, `[{]`, or `[}]`. For example, `x{1}.txt` is an alternation that matches `x1.txt`, so use `x[{]1[}].txt` for the file with that exact name. An escaped pattern is still a glob, so to also keep the contents of a directory named `backup[2025]`, specify `backup[[]2025]/**`. An unclosed `{` or `[`, or a lone `}`, is an invalid glob and fails with exit code 2.

### Filesystem Behavior

Windows uses the tool's Unicode simple case folding (non-Turkic); Ubuntu is case-sensitive. On Windows, `ä` and `Ä`, and `ß` and `ẞ`, are treated as equal, but `ß` and `SS` are not. The tool does not follow per-directory NTFS case-sensitivity settings. Windows and Ubuntu are supported.

A symbolic link supplied to `--root` is resolved to its target. Links under the processing directory are not followed and are treated as individual items. If a link is a deletion target, only the link is removed, not its target.

### Display and Execution

The default `--layout tree` shows kept items and deletion targets as a tree; `--layout flat` shows `ItemType` and `RelativePath` columns. Pattern matches and required ancestors are shown separately from deletion targets. See “Output and Options” for colors, markers, and sorting.

In a normal run, the tool displays both lists before asking for confirmation. Sections selected by `--summary` show counts instead of path lists. The answer is read as a whole line: `y` or `yes` (case-insensitive, ignoring surrounding whitespace) deletes. `n`, an empty Enter, any other answer, or end of input (EOF) cancels. The default is No; cancellation exits with code 3. `--force` skips only this prompt; invalid patterns or an invalid processing directory still produce an error.

If none of the supplied keep patterns matches any item, a warning is shown and everything under the processing directory becomes a deletion target.

## Output and Options

The output starts with a status label and the processing directory. When there are no deletion targets, the label is `NO REMOVALS`, including in a dry run. Otherwise, dry runs show `PREVIEW ONLY`, normal runs that require confirmation show `CONFIRM TO DELETE`, and `--force` shows `FORCE DELETE`. On a colored TTY, these labels are highlighted in green, cyan, yellow, and red, respectively. The labels and descriptions remain when color is disabled.

Preview header example:

```text
PREVIEW ONLY  Nothing will be removed
Root: S:\work\project
```

For human-readable output, ordinary Windows drive and UNC paths omit the `\\?\` prefix. Paths that would become ambiguous in ordinary notation, such as components ending in a space or period, retain the extended form. Control characters in file names and the processing-directory path are rendered visibly. Display formatting does not change the internal path or deletion targets.

### Layouts

| Layout | With color | Without color |
| --- | --- | --- |
| Tree (default) | Directories blue, symbolic links cyan, retained parents that appear only in the deletion list green | `/` for directories, `@` for symbolic links, `+` for retained parents |
| Flat | `ItemType` and `RelativePath` columns; directories blue, symbolic links cyan, files uncolored | `/` on directory paths, `@` on symbolic-link paths, no file marker |

Every entry in the deletion list is a deletion target; top-level deletion items are not marked separately. Flat layout has no retained-parent color or marker. `--sort-by-type` requires `--layout flat` and sorts by Directory, File, then Symlink, with relative-path order within each type. Without type sorting, items are displayed in relative-path order. Sorting affects display only, not the displayed lists or deletion order.

Examples:

```sh
remove-except --dry-run --layout flat keep.txt
remove-except --dry-run --layout flat --sort-by-type keep.txt
remove-except --dry-run --summary both keep.txt
```

### Legends and Summaries

When a full path listing is shown, a legend appears after the processing-directory path. With color, Tree legends list directories (blue), symlinks (cyan), and retained parents (green); Flat legends list directories (blue) and symlinks (cyan). Without color, `Markers:` explains `/`, `@`, and `+` for Tree, or `/` and `@` for Flat. On a TTY, `--help` subtly styles headings, Usage, option names, and values; it emits no ANSI styling when color is disabled.

`--summary keep|delete|both` replaces selected sections with counts and no paths. Keep counts include required ancestors and separately report direct pattern matches. Deletion-item counts and the number of top-level deletion operations are distinct. Since summaries omit paths, review every item with `--dry-run` and without `--summary` before deleting.

In the `human` format, kept items, deletion targets, and execution results are written to standard output. Warnings, errors, and confirmation prompts are written to standard error (see “JSON Output” for `--format json`). Human-readable output is not a stable format for parsing by other programs.

## Pipeline Integration

`--patterns-from-stdin` and `--format json` let you combine the tool with other commands in PowerShell or Bash. Passing patterns through standard input and receiving the plan as JSON can be used separately or together.

### Patterns from Standard Input

With `--patterns-from-stdin`, standard input is read as one pattern per line.

- Input must be UTF-8. If a line is not valid UTF-8 or contains a NUL character, the command reports its line number and exits with code 2. The command does not detect all BOM-less UTF-16: byte sequences without NUL may be interpreted as different, valid UTF-8 text. A single byte-order mark (BOM) at the start of the input is removed.
- Lines may end with LF or CRLF. Only the line terminator is removed; other whitespace is kept as part of the name. A CR at the end of a final line without a line terminator is also kept.
- Completely empty lines are ignored. A line containing only spaces is treated as a whitespace pattern.
- There is no comment syntax such as `#`.
- Each line is interpreted as a path or glob, just like a positional argument, not as a literal file name. When file names printed by another command are passed directly, names containing glob characters (`*`, `?`, `[`, `{`, `}`, and `\` on Ubuntu) may match other items or fail as invalid globs. A directory whose name contains glob characters does not keep its contents. See “Matching and Retention” for escaping and appending `/**`.
- Positional patterns may be combined with stdin patterns; all patterns use OR semantics. If no pattern remains after empty lines are ignored, the command fails.
- NUL-delimited input is not supported. File names containing newlines cannot be passed as patterns.
- Without a pipe or redirection, you can type patterns in the terminal, one per line. The command writes a note to standard error that it is waiting for input and how to finish. Finish input with Ctrl+D on Ubuntu, or Ctrl+Z followed by Enter on Windows.

Because standard input is used for patterns, the confirmation answer is read from the controlling terminal (the console on Windows, `/dev/tty` on Ubuntu). When no terminal is available, such as in CI or scheduled jobs, nothing is deleted and the command exits with code 3. In that case, preview with `--dry-run`, or use `--force` after reviewing the plan. Without `--patterns-from-stdin`, the confirmation answer is still read from standard input as before.

Bash example (keep only files tracked by Git, plus `.git`):

```bash
git -c core.quotePath=false ls-files | remove-except --dry-run --patterns-from-stdin .git
```

The `git ls-files` list does not include `.git` itself, so the example keeps `.git` with a positional argument. Without it, the repository's own `.git` also becomes a deletion target. Untracked and ignored files (such as build output and local settings) become deletion targets, so review every item with `--dry-run` before running the command for real.

Use this example as is only when tracked file names contain no newlines, tabs, `"`, `\`, or glob characters. Even with `core.quotePath=false`, Git prints names containing newlines, tabs, `"`, or `\` in quotes, so those files do not match and become deletion targets. Names containing glob characters may match other items.

PowerShell example (keep patterns listed in a file, plus `*.md`):

```powershell
Get-Content -Encoding UTF8 .\keep-list.txt | remove-except --dry-run --patterns-from-stdin '*.md'
```

When passing patterns from PowerShell or reading JSON output, use UTF-8 for text exchange. In Windows PowerShell 5.1, `$OutputEncoding`, which controls text sent to external commands, defaults to ASCII. In PowerShell 7 and later, it defaults to UTF-8, but the setting may have been changed. The following example configures UTF-8 for sending patterns and reading JSON output. No change is needed if the settings already use UTF-8.

```powershell
$utf8 = [System.Text.UTF8Encoding]::new($false)
$OutputEncoding = $utf8
[Console]::OutputEncoding = $utf8
```

`$OutputEncoding` controls how PowerShell sends strings to external commands; `[Console]::OutputEncoding` controls how PowerShell reads external-command output as strings.

### JSON Output

With `--format json`, the pre-deletion plan is written to standard output as exactly one JSON object. It contains no status label, legend, colors, or warnings. Warnings, confirmation prompts, and messages such as `Aborted.` and `Removal complete.` are written to standard error.

```json
{
  "schema_version": 1,
  "root": "/home/user/work",
  "direct_match_count": 1,
  "keep_items": [
    { "relative_path": "keep.txt", "type": "file" }
  ],
  "delete_items": [
    { "relative_path": "old", "type": "directory" },
    { "relative_path": "old/a.log", "type": "file" }
  ],
  "delete_roots": [
    { "relative_path": "old", "type": "directory" }
  ]
}
```

| Field | Contents |
| --- | --- |
| `schema_version` | Version of the JSON format. Currently `1`. |
| `root` | Absolute path of the normalized processing directory in native OS notation. On Windows it may start with `\\?\`. |
| `direct_match_count` | Number of items directly matched by a pattern. `0` means every item is a deletion target. |
| `keep_items` | All kept items, including pattern matches and their ancestor directories. |
| `delete_items` | All deletion targets. |
| `delete_roots` | Top-level deletion items passed to actual deletion. Descendants of deleted directories are not included. |

Each item has `relative_path` (a `/`-separated path relative to the processing directory) and `type` (`directory`, `file`, or `symlink`). Arrays are sorted by relative path. Paths are written as Unicode strings. If any path cannot be represented as Unicode (for example, a name containing invalid UTF-8 on Ubuntu), the command prints no JSON, deletes nothing, and exits with code 1.

`--format json` output is the plan before deletion, not the result of execution.

- With `--dry-run`: the plan is printed and nothing is deleted.
- Without `--dry-run`: the plan is printed, then confirmation is requested. A cancelled run exits with code 3. Because the JSON is printed before deletion, use the exit code (`0` for completed deletion, `3` for cancellation) to tell whether anything was deleted.
- With `--force`: the plan is printed, then items are deleted without confirmation.

`--summary`, `--layout`, and `--sort-by-type` are for human-readable output and cannot be combined with `--format json` (exit code 2).

Compatibility: fields may be added without changing `schema_version`; ignore unknown fields. Breaking changes, such as removing a field or changing its meaning, increment `schema_version`.

Bash example (list deletion targets with jq):

```bash
remove-except --dry-run --format json '**/*.md' | jq -r '.delete_items[].relative_path'
```

PowerShell example:

```powershell
$plan = remove-except --dry-run --format json '**/*.md' | ConvertFrom-Json
$plan.delete_items | Where-Object type -eq 'file' | ForEach-Object relative_path
```

When reading JSON in PowerShell, also check that it is decoded as UTF-8. See “Patterns from Standard Input” for the configuration example.

### Exit Codes

| Exit code | Meaning |
| --- | --- |
| `0` | The plan was shown, or deletion completed (including when there was nothing to delete). |
| `1` | Runtime error, such as a scan or deletion failure or a path that cannot be represented in JSON. |
| `2` | Invalid arguments, standard input, processing directory, or patterns. |
| `3` | Nothing was deleted because confirmation was declined or no terminal was available to confirm. |

If an error occurs during deletion (exit code 1), items already deleted are not restored.

## Versioning and Compatibility

Updates may change which items are kept or deleted, or how deletion is confirmed. Even a patch update may change deletion results by fixing a bug. Review the changes when updating and inspect the targets with `--dry-run` before deleting.
