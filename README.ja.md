# remove-except

[English](README.md) | [日本語](README.ja.md)

たくさんのファイルがあるディレクトリーから、必要なものだけを残し、下の階層も含めてそれ以外を削除したい。そんなことはありませんか。私はあります。もちろん、スクリプトを書けば実現できます。でも、残したいパスやパターンを指定するだけで済むコマンドがあれば、もっと手軽じゃないかと思いました。そこで作ったのが、指定した項目を残す `remove-except` です。

`remove-except` は、指定したパスや glob パターンのいずれかに一致する項目を保持し、選択した処理対象ディレクトリー配下のそれ以外を削除するコマンドラインツールです。

## 安全上の注意

このツールはファイルやディレクトリーを実際に削除します。実行前にバックアップを取り、削除前に必ず `--dry-run` を付けて全項目を確認してください。`--summary` はパスを省略するため、削除前の確認には使わないでください。指定した保持パターンのいずれにも一致する項目がない場合は、処理対象ディレクトリー配下のすべてが削除対象になります。特に `--force` を使う場合は、意図したパターンが項目に一致していることを確認してください。他のコマンドで生成したパターンを `--patterns-from-stdin` で渡す場合も、生成結果が意図どおりか `--dry-run` で確認してください。`--root` を指定した場合は、表示された処理対象ディレクトリーが意図した場所か確認してください。ファイルシステム最上位のディレクトリーは処理対象に指定できません。

## クイックスタート

コマンド書式は `remove-except [OPTIONS] [KEEP_PATTERN]...` です。位置引数には保持するパスまたはglobパターンを指定します。`--patterns-from-stdin` を使う場合は標準入力のパターンと合わせて1個以上指定し、複数のパターンはOR条件で扱います。

まず `--dry-run` で、保持される項目と削除対象を確認します。

```sh
remove-except --dry-run keep.txt keep '**/*.md'
```

削除を実行するときは `--dry-run` を外します。通常実行では保持項目と削除対象を表示してから確認を求めます。確認入力の規則は「表示と実行」を参照してください。`--force` を指定すると確認なしで削除しますが、無効なパターンや処理対象ディレクトリーを指定した場合はエラーになります。

```sh
remove-except keep.txt keep '**/*.md'
remove-except --force keep.txt keep '**/*.md'
```

別の処理対象ディレクトリーは `--root` で指定します。相対パスはコマンド起動時のカレントディレクトリー基準です。

```sh
remove-except --root work --dry-run keep.txt '**/*.md'
```

## パターンと処理ルール

### 実行例

次の構成で、`work` ディレクトリーをカレントディレクトリーにして実行する例です。

```text
work/
├── keep.txt
├── readme.md
├── todo.txt
├── reports/
│   ├── summary.txt
│   ├── report1.csv
│   ├── report2.csv
│   └── 2025/
│       ├── annual.csv
│       └── notes.txt
└── archive/
    └── old.csv
```

### glob の指定

保持したいパスは、glob（globパターン）で指定できます。`*` や `?` などの記号を使って、項目名の一部や階層を表します。ファイル、ディレクトリー、シンボリックリンクが対象になります。複数のパターンは空白で区切ります。

```sh
remove-except --dry-run '**/*.md'
```

この構成では `readme.md` が保持され、`keep.txt`、`todo.txt`、`reports`、`archive` などは削除対象として表示されます。プレビューには保持対象と削除対象の両方が表示されます。

よく使う glob 記号は次のとおりです。

| パターン例 | 意味 |
| --- | --- |
| `*.md` | 処理対象ディレクトリー直下で `.md` で終わる項目の相対パスです。`*` は `/` をまたぎません。 |
| `**/*.md` | 直下と下位ディレクトリーで `.md` で終わる項目の相対パスです。`**/` は0階層以上のディレクトリーに一致します。 |
| `reports/report?.csv` | `?` は `/` 以外のUnicode scalar値を1個照合します。この構成では `report1.csv` と `report2.csv` に一致します。 |
| `reports/report[12].csv` | `[]` は指定したUnicode scalar値のいずれか1個に一致します。この構成では `report1.csv` と `report2.csv` に一致します。 |

特定のサブディレクトリー以下に glob を限定する場合は、処理対象ディレクトリーからの相対パスにそのディレクトリーを含めます。

```sh
remove-except --dry-run 'reports/**/*.csv'
```

この構成では `reports/report1.csv`、`reports/report2.csv`、`reports/2025/annual.csv` が保持されます。glob は引用符で囲んで、シェルによる事前展開を防いでください。

### サブディレクトリーの指定

サブディレクトリー全体を残す場合は、ディレクトリー名をそのまま指定します。

```sh
remove-except --dry-run reports/2025
```

`reports/2025` とその中身はすべて保持されます。たとえば `annual.csv` と `notes.txt` は残りますが、`reports/summary.txt` や `reports/report1.csv` は削除対象です。

サブディレクトリー内の1ファイルだけを残す場合は、処理対象ディレクトリーからの相対パスを指定します。

```sh
remove-except --dry-run reports/2025/annual.csv
```

この場合は `annual.csv` と親ディレクトリー `reports`、`reports/2025` が保持されます。同じディレクトリーにある `notes.txt` は削除対象です。

サブディレクトリー以下の特定の拡張子を残す場合は、その場所と glob を組み合わせます。

```sh
remove-except --dry-run 'reports/2025/*.csv'
```

この構成では `reports/2025/annual.csv` が保持され、`reports/2025/notes.txt` は削除対象です。`*` はその階層だけに一致するため、`reports/2025/*.csv` は `reports/2025` 直下の `.csv` で終わるパスに一致します。配下の複数階層を対象にする場合は `reports/2025/**/*.csv` を使います。ディレクトリー全体を残す場合は、globではなく `reports/2025` のように指定します。

### 処理対象とパス

既定では、コマンド起動時のカレントディレクトリー以下を再帰的に処理します。`--root` で別の処理対象ディレクトリーを指定できます。指定したディレクトリー自体は一覧にも削除対象にも含まれません。ファイルシステム最上位のディレクトリーは処理対象にできません。

保持パターンは1個以上必須です。複数指定した場合、いずれか1個に一致すれば保持します。パターンは位置引数、または `--patterns-from-stdin` を付けた標準入力で指定します（「パイプラインとの連携」を参照）。先頭や末尾の空白も名前の一部として照合されるため、空白を含むパターンはシェルで引用符に囲み、1つの引数として渡してください。

相対パターンは処理対象ディレクトリーを基準に解釈します。絶対パターンは、そのディレクトリー配下を指す場合だけ受理されます。相対パターンでは `.` 要素と繰り返しの区切りを正規化します。絶対パターンは処理対象ディレクトリーと照合し、一致部分より後の `.` 要素と繰り返し区切りを正規化します。一致部分内は正規化しません。Windowsでは照合前に `\` を区切りの `/` にそろえます。Ubuntuでは `\` は区切りではなく、globのエスケープ文字です。

絶対パターンは、シンボリックリンクなどを解決した後の処理対象ディレクトリー（出力の `Root:` に表示されるパス）と照合します。`--root` やカレントディレクトリーがリンクを経由している場合、リンク側のパスで書いた絶対パターンは処理対象ディレクトリー外とみなされてエラーになります。この場合は相対パターンを使ってください。

処理対象ディレクトリーの外を指す絶対パターン、`..` を含むパターン、空のパターン、Windowsの曖昧なdrive-relative path（例: `C:folder`）はエラーになります。

### globと項目の保持

パターンには `*`、`**`、`?`、文字クラス `[]`、選択肢 `{a,b}` を使えます。ファイル、ディレクトリー、シンボリックリンクが照合対象です。`*`、`**`、`?`、文字クラスの例と階層の規則は前の例を参照してください。選択肢と照合後の保持規則はこの節の後半を参照してください。

`?` と文字クラスは、1バイトや見た目上の1文字ではなく、Unicode scalar値を1個ずつ照合します。基底文字と結合文字で構成される文字は、複数の `?` が必要です。

Ubuntuでは、名前に改行が含まれる項目も `**` の照合対象です。リテラルのバックスラッシュは `\\` としてエスケープでき、直後に `x80` などが続いても16進エスケープにはなりません。Unicode照合の修正後は、以前のUbuntuのバイト単位の照合とは保持・削除結果が変わる場合があります。削除前に `--summary` なしの `--dry-run` で全項目を確認してください。

一致した項目とその親ディレクトリーは保持しますが、一致した項目の子孫までは自動で保持しません。globを含まないディレクトリーパスを指定すると、そのディレクトリー全体を保持します。`dir/*` は `dir` 直下の項目だけに一致し、子ディレクトリーの中身は保持しません。`.` または `./` は処理対象ディレクトリーを表し、その配下をすべて保持します。

glob記号は `*`、`?`、`[`、`{`、`}` です。Ubuntuでは `\` もエスケープ文字としてglob記号に含まれます。これらを1つでも含むパターンはglobとして扱い、一致したディレクトリーの中身は保持しません。たとえば `reports/{2024,2025}` は2つのディレクトリーだけを保持します。中身も残すには `reports/{2024,2025}/**` のように `/**` を付けるか、`reports/2024` と `reports/2025` を別々に指定してください。

`dir/**` は `dir` 配下の項目に一致しますが、`dir` 自体には一致しません。`dir` が空の場合は削除対象になります。空の場合も含めてディレクトリーを残すには、globを含まない `dir` を指定してください。

glob記号を名前の文字として照合するには、`[*]`、`[?]`、`[[]`、`[{]`、`[}]` のように文字クラスで囲みます。たとえば `x{1}.txt` は選択肢として解釈されて `x1.txt` に一致するため、名前どおりのファイルには `x[{]1[}].txt` を指定します。エスケープしてもglobとして扱うため、`backup[2025]` というディレクトリーの中身も残すには `backup[[]2025]/**` を指定します。閉じていない `{` や `[`、単独の `}` は無効なglobとしてエラーになります（終了コード2）。

### ファイルシステム上の挙動

Windowsではツール独自のUnicode単純ケースフォールド（非トルコ語）で照合し、Ubuntuでは大文字と小文字を区別します。Windowsでは `ä` と `Ä`、`ß` と `ẞ` を同一視しますが、`ß` と `SS` は同一視しません。NTFSのディレクトリー単位のケースセンシティブ設定には追従しません。サポート対象はWindowsとUbuntuです。

`--root` にシンボリックリンクを指定した場合はリンク先を処理します。処理対象ディレクトリー配下のリンクはたどらず、1項目として扱います。削除対象の場合もリンクだけを削除し、リンク先は削除しません。

正規化後の処理対象ディレクトリーと、走査した全項目のパスはUnicodeとして表せる必要があります。不正なUTF-8を含むUbuntuの名前や、単独サロゲートを含むWindowsの名前がある場合、計画を生成せず、標準出力への出力・削除前に終了コード1で停止します。保持予定の項目も対象で、human／JSON、Tree／Flat、`--summary`、`--dry-run`、`--force` にかかわらず適用します。配下のシンボリックリンクのリンク先は検査しません。正しいUnicodeの置換文字 `�`（U+FFFD）を含む名前は受理します。

### 表示と実行

Tree表示は保持項目と削除対象をツリーで示し、Flat表示は `ItemType` と `RelativePath` の一覧を示します。パターンに一致した項目と必要な祖先は、削除対象とは別に表示します。色、記号、並び順は「出力とオプション」を参照してください。

通常実行では保持項目と削除対象を表示した後に確認します。ただし、`--summary` で指定した節はパス一覧の代わりに件数を表示します。改行で終わる1行の回答が `y` または `yes`（大文字と小文字は区別せず、前後の空白は無視）の場合だけ削除します。Enterのみ、改行なしの回答、その他の入力、入力の終了（EOF）では中止します。既定は「いいえ」で、中止時は終了コード3です。`--force` は確認だけを省略し、無効なパターンや処理対象ディレクトリーの検証は省略しません。指定した保持パターンのどれにも項目が一致しない場合は警告を出し、処理対象ディレクトリー配下の全項目が削除対象になります。

人向け表示の最終確認直前には、処理対象ディレクトリー、保持件数（必要な祖先を含む）、直接一致数、削除項目数、最上位の削除操作数を標準エラーへ再掲します。未一致・サマリーによるパス省略の警告も再掲します。これは全件の確認を置き換えるものではありません。JSON、`--force`、`--dry-run`、削除対象なしの場合には、この最終確認用の再掲はありません。

## 出力とオプション

出力の先頭に状態ラベルと処理対象ディレクトリーを表示します。削除対象がない場合は、dry-runを含めて `NO REMOVALS` を表示します。それ以外ではdry-runに `PREVIEW ONLY`、確認付きの通常実行に `CONFIRM TO DELETE`、`--force` に `FORCE DELETE` を表示します。色付きTTYではそれぞれ緑、シアン、黄色、赤で強調します。色なしでも同じラベルと説明を表示します。

プレビュー冒頭の例:

```text
PREVIEW ONLY  Nothing will be removed
Root: S:\work\project
```

通常のWindowsドライブパスやUNCパスは、人向け表示では `\\?\` を省きます。末尾が空白やピリオドの要素など、通常表記では曖昧になるパスは拡張形式を維持します。ファイル名や処理対象ディレクトリーのパスに含まれる制御文字は可視化し、表示によって内部のパスや削除対象が変わることはありません。

| レイアウト | 色あり | 色なし |
| --- | --- | --- |
| Tree（既定） | ディレクトリーは青、シンボリックリンクはシアン、削除一覧にだけ現れる保持済み親は緑 | ディレクトリーに `/`、シンボリックリンクに `@`、保持済み親に `+` |
| Flat | `ItemType` と `RelativePath` 列。ディレクトリーは青、シンボリックリンクはシアン、ファイルは無色 | ディレクトリーの相対パスに `/`、シンボリックリンクに `@`、ファイルは印なし |

削除一覧の各項目は削除対象です。最上位の削除項目を区別する印は使いません。Tree表示は各ディレクトリーの直下項目を名前順に並べ、そのディレクトリーの部分木を続けて表示します。Flat表示は型別ソートを指定しない場合、相対パス順です。`--sort-by-type` はFlat表示でのみ使え、Directory → File → Symlink の順に並べ、各種類内は相対パス順です。これらの順序変更は表示だけに適用され、対象一覧や削除順を変えません。

レイアウトやサマリーを指定する例:

```sh
remove-except --dry-run --layout flat keep.txt
remove-except --dry-run --layout flat --sort-by-type keep.txt
remove-except --dry-run --summary both keep.txt
```

### 凡例とサマリー

パスを表示する一覧がある場合だけ、処理対象ディレクトリーの直後に凡例を表示します。色ありではTreeにディレクトリー（青）、シンボリックリンク（シアン）、保持済み親（緑）を、Flatにディレクトリー（青）とシンボリックリンク（シアン）を示します。色なしではTreeに `/`、`@`、`+` の意味を、Flatに `/` と `@` の意味を説明します。

TTY上の `--help` は見出し、Usage、オプション名、値を控えめに装飾します。色が無効な場合はANSI装飾を出しません。

`--summary keep|delete|both` は選択したセクションをパスなしの件数表示にします。保持件数には必要な祖先を含み、直接一致数は別に示します。削除項目数と、実際に削除関数へ渡す最上位項目数も区別します。サマリーではパスを確認できないため、削除前には必ず `--summary` なしの `--dry-run` で全件を確認してください。

色付きTTYでは、サマリーの `KEEP:` を緑、`DELETE:` を赤の太字で表示します。色が無効な場合は装飾しません。

`human` 形式では、保持項目と削除対象、および実行結果は標準出力、警告・エラー・確認プロンプトは標準エラーに出力します（`--format json` の出力先は「JSON出力」を参照）。`human` 形式の標準出力は人向けで、別プログラムから解析する安定した形式ではありません。

### 大量項目の閲覧

`--pager auto`（既定）は、通常実行または `--dry-run` の人向け一覧が端末画面に収まらない場合に内蔵ビューアーを起動します。Tree／Flatとサマリーの指定を維持し、長いパスは省略せず折り返します。処理対象ディレクトリー、状態、表示位置、操作案内を表示し、画面サイズ変更に合わせて再配置します。

折り返しは結合文字やZWJ絵文字などの書記素クラスタを分断せず、文字列全体の表示幅に基づきます。実際の見え方は端末やフォントによって異なる場合があります。1つのクラスタが行幅に収まらない場合も画面領域不足として扱い、開始前のautoは理由付きで通常出力、alwaysは終了コード1、開始後は何も削除せず終了コード1で停止します。

位置表示は、画面内に保持セクションがあれば `KEEP`、削除セクションがあれば `DELETE`、両方あれば `KEEP + DELETE`、冒頭の案内などだけなら `PLAN` を示します。Tab／Shift+Tabは移動可能なセクション位置を循環します。両セクションの移動先が同じ場合（全体が一画面に収まる場合など）はスクロールしません。

色ありの位置表示では、`KEEP` は緑＋太字、`DELETE` は赤＋太字、`PLAN` はシアン＋太字です。`KEEP + DELETE` は各ラベルをそれぞれの色で示し、区切りと行番号は通常色のままにします。

| 操作 | 動作 |
| --- | --- |
| ↑ / ↓ | 1表示行ずつ移動 |
| PageUp / PageDown | ページ移動 |
| Home / End | 先頭 / 末尾へ移動 |
| Tab / Shift+Tab | 保持 / 削除セクション間の移動 |
| `c` | 閲覧完了。通常実行では別途最終確認へ進み、dry-run・削除対象なしでは終了コード0 |
| `q` / Esc / Ctrl+C | 閲覧を中止。何も削除せず終了コード3 |

閲覧中のEnterや`y`では削除しません。閲覧完了時には未処理の閲覧入力を破棄し、端末状態を復元してから、制御端末で新たな確認回答を1行読み取ります。閲覧・確認・削除には同じ計画を使いますが、閲覧中に他のプログラムがファイルを変更することまで防ぐものではありません。

最終確認直前の `Review before deletion:` は、標準エラーの端末・色設定に従い、見出しを黄＋太字、`Root:` を太字、`KEEP:` を緑＋太字、`DELETE:` を赤＋太字で再掲します。保持一致なし・サマリー省略の注意は黄色で、見出しを太字にします。パス・件数・通常の補足は通常色です。ビューアーの色は標準出力側で判断し、要点再掲とは独立しています。色が無効、または各出力先がリダイレクトされている場合、装飾せず同じ文言を表示します。

`--pager always` は短い一覧でも起動し、JSONまたは `--force` との併用は引数エラーです。`--pager never` は従来の通常出力にします。既定のautoでは、JSONや `--force`（`--dry-run` との併用を含む）はビューアーを使用しません。

標準出力が非TTY、制御端末がない、端末が非対応、または画面が小さすぎる場合、autoは理由を標準エラーに示して通常出力へ切り替えます。alwaysは削除せず終了コード1です。確認の回答を標準入力から読む通常実行（`--dry-run` ではなく削除対象がある場合）では、`--patterns-from-stdin` ではない標準入力リダイレクトも、回答用の入力を横取りしないため同じ扱いです。`--dry-run` や削除対象なしの実行は確認の回答を読まないため、標準入力がリダイレクトされていても、対応する出力端末と制御端末があればビューアーを使用できます。`--patterns-from-stdin` のパイプ入力も同じ条件でビューアーと併用できます。

開始後の端末入出力・状態復元の失敗は、通常出力に切り替えて続行せず、削除前に終了コード1で停止します。ビューアーによって保持・削除の判定や削除順序は変わりません。検索・折りたたみ・対話的な計画編集には対応していません。

```sh
remove-except --dry-run --pager always keep.txt
remove-except --pager never keep.txt
```

## パイプラインとの連携

`--patterns-from-stdin` と `--format json` を使うと、PowerShellやBashで他のコマンドと組み合わせられます。標準入力でパターンを渡す方向と、JSONで計画を受け取る方向は、それぞれ単独でも同時にも使えます。

### 標準入力からのパターン

`--patterns-from-stdin` を指定すると、標準入力を1行1パターンとして読み込みます。

- 入力はUTF-8にしてください。UTF-8として不正な行やNUL文字を含む行があると、行番号を示してエラー終了します（終了コード2）。BOMのないUTF-16を判定するものではありません。UTF-16のバイト列にNUL文字が含まれない場合、別のUTF-8文字列として解釈されることがあります。入力の先頭にあるBOMは1個だけ取り除きます。
- 改行はLFとCRLFのどちらも使えます。行末の改行文字だけを取り除き、それ以外の空白は名前の一部として残します。改行のない最終行の末尾にあるCRも残します。
- 完全に空の行は無視します。空白だけの行は空白のパターンとして扱います。
- `#` などのコメント構文はありません。
- 各行はファイル名そのものではなく、位置引数と同じパスまたはglobとして解釈します。他のコマンドが出力したファイル名をそのまま渡すと、glob記号（`*`、`?`、`[`、`{`、`}`、Ubuntuでは `\` も）を含む名前は別の項目に一致したり、無効なglobとしてエラーになったりします。また、glob記号を含む名前のディレクトリーは中身を保持しません。記号のエスケープと `/**` の付け方は「globと項目の保持」を参照してください。
- 位置引数のパターンと併用でき、すべてをOR条件で扱います。空行を除いた結果、パターンが1個もなければエラーになります。
- NUL区切りの入力には対応していません。改行を含むファイル名はパターンとして渡せません。
- パイプやリダイレクトを使わずに実行すると、端末からパターンを1行ずつ入力できます。入力待ちであることと終了方法を標準エラーに表示します。入力の終了はUbuntuではCtrl+D、WindowsではCtrl+Zを押してからEnterです。

標準入力はパターンの読み込みに使うため、確認の回答は制御端末（Windowsのコンソール、Ubuntuの `/dev/tty`）から読み取ります。端末がない場合（CIやスケジュール実行など）は何も削除せず、終了コード3で終了します（`--pager always` の起動失敗は終了コード1）。この場合は `--dry-run` で確認するか、内容を確認したうえで `--force` を使ってください。`--patterns-from-stdin` を指定せず、内蔵ビューアーも使用しない場合は、従来どおり標準入力から確認の回答を読み取ります。

Bashの例（Gitで管理しているファイルと `.git` だけを残す場合）:

```bash
git -c core.quotePath=false ls-files | remove-except --dry-run --patterns-from-stdin .git
```

`git ls-files` の一覧には `.git` 自体が含まれないため、位置引数で `.git` を保持します。指定しないと、リポジトリー本体の `.git` も削除対象になります。Gitで追跡していないファイルやignore対象のファイル（ビルド成果物やローカル設定など）は削除対象になるため、`--dry-run` で全件を確認してから実行してください。

この例は、追跡しているファイル名に改行、タブ、`"`、`\`、glob記号が含まれない場合だけ、そのまま使えます。`core.quotePath=false` を指定しても、Gitは改行、タブ、`"`、`\` を含む名前を引用符付きで出力するため、それらのファイルは一致せず削除対象になります。glob記号を含む名前は、別の項目に一致することがあります。

PowerShellの例（一覧ファイルに書いたパターンと `*.md` を残す場合）:

```powershell
Get-Content -Encoding UTF8 .\keep-list.txt | remove-except --dry-run --patterns-from-stdin '*.md'
```

PowerShellからパターンを渡したり、JSON出力を読み取ったりする場合は、文字列の受け渡しにUTF-8を使ってください。Windows PowerShell 5.1では、外部コマンドへ文字列を送る `$OutputEncoding` の既定値はASCIIです。PowerShell 7以降では既定でUTF-8ですが、設定が変更されている場合もあります。以下は、パターンの送信とJSON出力の読み取りをUTF-8に揃える設定例です。既にUTF-8なら変更は不要です。

```powershell
$utf8 = [System.Text.UTF8Encoding]::new($false)
$OutputEncoding = $utf8
[Console]::OutputEncoding = $utf8
```

`$OutputEncoding` はPowerShellの文字列を外部コマンドへ送る際の設定、`[Console]::OutputEncoding` は外部コマンドの出力をPowerShellで文字列として読み取る際の設定です。

### JSON出力

`--format json` を指定すると、削除前の計画をJSONオブジェクト1個として標準出力に出力します。状態ラベル、凡例、色、警告は含みません。警告、確認プロンプト、`Aborted.`、`Removal complete.` などのメッセージは標準エラーに出力します。

```json
{
  "schema_version": 1,
  "root": "/home/user/work",
  "direct_match_count": 1,
  "keep_items": [
    { "relative_path": "keep.txt", "type": "file" }
  ],
  "delete_items": [
    { "relative_path": "old", "type": "directory" },
    { "relative_path": "old/a.log", "type": "file" }
  ],
  "delete_roots": [
    { "relative_path": "old", "type": "directory" }
  ]
}
```

| フィールド | 内容 |
| --- | --- |
| `schema_version` | JSON形式のバージョン。現在は `1` です。 |
| `root` | 正規化された処理対象ディレクトリーの絶対パス。OS本来の表記で、Windowsでは `\\?\` で始まる場合があります。 |
| `direct_match_count` | パターンに直接一致した項目数。`0` の場合は全項目が削除対象です。 |
| `keep_items` | 保持する項目すべて。パターンに一致した項目と、その祖先ディレクトリーを含みます。 |
| `delete_items` | 削除対象の項目すべて。 |
| `delete_roots` | 実際に削除処理へ渡す最上位の削除項目。削除対象ディレクトリーの子孫は含みません。 |

各項目は `relative_path`（処理対象ディレクトリーからの `/` 区切りの相対パス）と `type`（`directory`、`file`、`symlink` のいずれか）を持ち、配列は相対パス順に並びます。パスはUnicode文字列で出力します。Unicodeとして表せないパス（Ubuntu上の不正なUTF-8を含む名前など）がある場合は、JSONを出力せず、何も削除せずにエラー終了します（終了コード1）。

`--format json` の出力は削除前の計画で、実行後の結果ではありません。

- `--dry-run` 付き: 計画を出力するだけで、何も削除しません。
- `--dry-run` なし: 計画を出力した後、確認します。中止した場合は終了コード3です。JSONは削除前に出力されるため、実際に削除したかどうかは終了コード（`0` なら削除完了、`3` なら中止）で判断してください。
- `--force` 付き: 計画を出力した後、確認なしで削除します。

`--summary`、`--layout`、`--sort-by-type` は人向け表示用のため、`--format json` とは併用できません（終了コード2）。

互換性: 同じ `schema_version` のまま、フィールドが追加される場合があります。未知のフィールドは無視してください。既存フィールドの削除や意味の変更など、互換性を壊す変更では `schema_version` を上げます。

Bashの例（jqで削除対象の相対パスを一覧する場合）:

```bash
remove-except --dry-run --format json '**/*.md' | jq -r '.delete_items[].relative_path'
```

PowerShellの例:

```powershell
$plan = remove-except --dry-run --format json '**/*.md' | ConvertFrom-Json
$plan.delete_items | Where-Object type -eq 'file' | ForEach-Object relative_path
```

PowerShellでJSONを読み取る場合も、UTF-8として受け取る設定を確認してください。設定例は「標準入力からのパターン」を参照してください。

### 終了コード

| 終了コード | 意味 |
| --- | --- |
| `0` | 計画を表示した、または削除が完了した（削除対象がない場合を含む） |
| `1` | 実行時エラー（走査や削除の失敗、Unicodeで表せないパス、明示したビューアーの起動失敗、閲覧中の端末エラーなど） |
| `2` | 引数、標準入力、処理対象ディレクトリー、パターンの不備 |
| `3` | 閲覧・確認で中止した、または確認できる端末がなく、何も削除しなかった |

削除中にエラーが起きた場合（終了コード1）、それ以前に削除済みの項目は元に戻りません。

## バージョンと互換性

### v0.3.0 から v0.4.0 への更新

- 非Unicodeパスの拒否をJSON以外の出力と公開APIにも適用します。v0.3.0ではhuman表示や照合時に異なる名前が同じ置換文字列になる場合がありました。曖昧なプレビューや保持判定を避けるため、計画生成時にエラーにします。ライブラリーの `build_plan` は計画を返さず、`ValidationError` ではない実行時エラーを返します。CLIは `--force` を含む全実行モードで、標準出力・確認・削除より前に終了コード1で停止します。従来成功していた入力でも停止する互換性変更です。正しいUnicode置換文字（U+FFFD）を含む名前は引き続き利用できます。
- Ubuntuの `?` と文字クラスをUTF-8のバイト単位ではなくUnicode scalar値単位で照合するよう修正しました。結合文字列は複数のscalar値として扱い、Ubuntuの大文字・小文字を区別する規則は維持します。以前とは保持対象・削除対象が変わる場合があります。改行入りの名前への `**` の一致と、バックスラッシュを含むパターンも回帰テストで確認しています。
- 改行なしの `y` / `yes` とEOFで削除する不具合を修正しました。v0.3.0の文書はEnterによる確定・EOF中止を説明していましたが、配布実装は未終端の肯定回答も受理していました。全入力経路で改行終端の肯定行だけを受理し、それ以外は何も削除せず終了コード3で中止します。
- Tree表示ではディレクトリーの部分木を連続して表示し、似た接頭辞の兄弟名によるノードの重複表示を修正しました。Flat・JSON・計画の相対パス順や削除順序は変えません。色ありのサマリーでは `KEEP:` を緑、`DELETE:` を赤で表示します。
- Rust Docの例は所有する一時ディレクトリーを使うよう修正しました。走査が原子的なスナップショットではなく、同時変更を防がないことも明確にしました。新たなロックや再検証の保証を追加するものではありません。
- 公開APIの型、JSONの `schema_version: 1`、最低Rustバージョン1.88、Windows／Ubuntuの対応範囲は維持します。更新後は `--summary` なしの `--dry-run` で全対象を確認してください。

### v0.2.4 から v0.3.0 への更新

- glob の分類に波括弧（`{` と `}`）と、Ubuntu のバックスラッシュによるエスケープ（`\`）を含めるよう修正しました。これらのパターンでは、リテラルなディレクトリー指定による配下全体の保持を行いません。以前は保持されていた子孫が削除対象になる場合があります。`reports/{2024,2025}` は一致するディレクトリーだけを保持し、中身は保持しません。子孫も残す場合は `reports/{2024,2025}/**` を指定してください。更新後は `--summary` なしの `--dry-run` で全項目を確認してください。
- 確認を全入力経路で1行単位に統一し、通常は `y` または `yes` を入力してEnterで確定する方式にしました（大文字と小文字は区別せず、前後の空白は無視）。ただし、v0.3.0の配布実装には改行なしの肯定回答も受理する不具合があり、v0.4.0で修正しました。中止の終了コードは `0` から `3` に変わり、引数・stdin 入力・処理対象ディレクトリー・パターンの不備は `2` です。終了コードや1キーでの確認に依存するスクリプトは見直してください。
- `--pager auto` により、端末に収まらない一覧には閲覧段階が加わります。通常出力には `--pager never` を使います。ビューアーは保持・削除判定や削除順序を変えません。`c` は閲覧完了だけを意味し、閲覧中の Enter や `y` では削除しません。最終確認は別に行い、要点を標準エラーに再掲します。stdin パターンを使う場合と閲覧後の確認は、stdin ではなく制御端末から読み取ります。
- `--patterns-from-stdin` で UTF-8 の改行区切り保持パターン、`--format json` で `schema_version: 1` の削除前計画を扱えるようになりました。人向け出力は安定した機械可読形式ではありません。ライブラリーでは、新しい `ValidationError` 型で入力検証エラーを識別できます。
- 最低 Rust バージョンは引き続き 1.88 です。計画は走査中に観測した項目を記録したものであり、走査は原子的または保護されたファイルシステムのスナップショットではなく、同時変更も防止しません。計画は作成後に更新されないため、プレビューから削除までの間にファイルが変わる可能性があります。保持一致なしの警告、処理対象ディレクトリーの検証、シンボリックリンクをたどらない動作は維持します。`--force` が省略するのは確認だけです。

更新によって保持対象・削除対象や確認手順が変わる場合があります。Patch 更新でも、不具合修正によって削除結果が変わることがあります。更新時は変更内容を確認し、実行前に `--dry-run` で対象を確認してください。
